两个硬件方案，一套协议栈

怎么认出这是哪台设备

广播名是唯一的识别依据；MAC 尾段只用来区分同型号的多台，不参与协议判断。

连上以后发生了什么

传输层连上就自动握手；上层要设备时直接 await，不需要关心底下是蓝牙还是 USB。

1

传输层连上 · 认出方案

按广播名或 GATT 服务找到档案，transport.hardwareProfile 就绪；读特征、订阅通知。

2

协议门面自动握手

DeviceSessionManager 监听连接状态，调用 profile.createSession(transport) 建立会话，然后发 hello、拉能力清单。

3

射频层选卡 · 认屏幕

EpdSession.activate() 走唤醒 → 防冲突 → 选卡 → RATS，然后按 D1 的 TLV 读出屏幕档案（几何、颜色数、压缩支持、UID）。

4

刷图 / 读卡

刷图走 core/epd（D1 → PIN → D3 → D4 → DE），读卡走 core/nfc；两者都只通过 rawTransceive() 与设备对话。

以后要加第三台设备

三步，全部落在协议层内；视图、射频、传输三层一行都不用改。

  1. 建目录 core/protocol/<方案>/ 写档案：scheme、label、GATT UUID、firmwareTarget.chipId、射频预设，以及 createSession(channel)。协议真分叉时，会话实现也在这里单独写。
  2. 在 hardware.ts 的 PROFILES 登记 登记后广播名里的方案号才会被认出来，能力过滤与设备选择器也会自动带上它。
  3. 在 core/protocol/index.ts 导出档案 对外暴露这个方案的档案，其余代码不需要知道它的存在。
分叉时的边界： 帧格式、消息契约、能力 ID、射频预设或芯片型号变了，就在该方案目录里单独实现， 不动 a01/，也不动射频桥与视图层。 这正是当初把 B01 单独建目录的原因 —— 今天它复用 A01 的会话实现，将来分叉时改动有地方落。
