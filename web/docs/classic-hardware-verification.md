## 最新实测修正：A01 Classic 接收增益

在同一 UID、Key A、卡片位置、功率 1 档下交错比较 RxAna（0x39）设置：

| RxAna | 认证及回读成功次数 |
| --- | --- |
| 原配置 0x0A | 0 / 3 |
| 0x08 | 3 / 3 |
| 0x09 | 3 / 3 |
| 0x0B | 0 / 3 |

选择保留高通参数、将接收增益限制为 01 的 0x09 后，对块 1、5、9、12 连续做三轮验证，12 次认证及回读全部通过。随后使用 Chrome 网页实际入口完成手动块 1 读取 5 次和工具箱 8 块读取 1 次；总共只有 9 次 MFAUTHENT，即没有触发重读。每次手动读取与整次料盘读取结束，都实读寄存器确认恢复到原值 0x0A。

本轮修正在 `A01Session.prepareClassicRf` 中实现。使用现有 raw RF 1.2 的寄存器接口临时调整 RxAna 的增益位，保留其他位；Classic 会话结束时恢复。通用 RF 桥只转交会话准备和清理，其他硬件方案没有该钩子时不调整。没有增加重试次数、切换密钥或忽略 ERROR，也没有改写固件或卡片。当前固件 0.2.1 无需 OTA，刷新网页并重新连接即可使用。

该结果支持接收增益是本机当前近场摆放下失败的重要因素，但未测量天线、电源或模拟波形，不能据此断言所有板卡和摆放距离都已验证。增益位和高通位定义参见 [NXP CLRC663 数据手册 9.12.6 节](https://www.nxp.com/docs/en/data-sheet/CLRC663.pdf)。

## 实物验证方法

1. 本机 CoreBluetooth / Bleak 连接真实 A01。中转仅搬运 GATT 字节，不模拟射频、认证结果或卡片数据。
2. 先在 Node 中直接加载 Web 的 A01Session、RfBridge、activateTag 和 MifareClassicSession，使用当前 UID 派生的密钥完成认证和块读取。
3. Chrome 打开本地 Web 界面，将真实 BLE 字节通道接到当前 A01Session；点击「读取并识别卡片 → 存储 → 读取料盘」，等待页面显示「8 个数据块读取完成」。该测试覆盖网页交互与全部协议层，未覆盖浏览器原生蓝牙选择器。
4. 检查操作记录：65 个作业，包含选卡、认证和读取，没有 A0 / A2 写卡命令。页面无运行异常；1024×600 与 1920×1080 没有横向溢出。读取结束清除控制器密钥并关闭射频场。

验证未刷写固件，也未更改卡片内容或密钥。截图与原始测试记录保存于本机临时目录：`/tmp/d4u-bambu-real-ui.png`、`/tmp/d4u-bambu-ui-result.json`。

## KDF 与实现

依据 [Bambu Research Group 的 deriveKeys.py](https://github.com/Bambu-Research-Group/RFID-Tag-Guide/blob/main/deriveKeys.py) 与[数据块说明](https://github.com/Bambu-Research-Group/RFID-Tag-Guide/blob/main/BambuLabRfid.md)，使用标签 UID 作为 HKDF-SHA256 输入，公开盐值与 `RFID-A\0` 上下文生成 96 字节，再按 6 字节划分 16 个扇区 Key A。网页用 Web Crypto 独立实现，没有引入 Python 或远程服务依赖。

内部派生密钥数组在结束或失败后清零；不写入日志或浏览器存储。按用户要求，工具箱现显示本次验证使用的扇区、块号与 Key A，以及 UID 和派生参数；显示值仅保留在本页内存中，重新识别、断开或离开页面后清除。每个扇区重新选卡并核对 UID，扇区内复用 Crypto1 会话。结果保留读取的数据块。此功能读取公开研究定义的字段，没有验证 RSA 签名，也不提供料盘改写。

## 仍存在的射频不稳定

使用正确派生密钥后认证可通过，但仍观察到偶发 PROTERR / INTEGERR / COLLDET。首次按扇区读取的实物测试在扇区 3 的两次认证中失败；随后完整浏览器测试在重新选卡后成功恢复并读取全部 8 块。只读操作遇到明确射频错误时重读该扇区一次；持续错误会停止，不返回伪造或不完整的料盘结果。一次成功不代表长期稳定性已验证。

对照了认证前 CRC 配置 0、1、2、3。没有足够证据证明某一配置能稳定消除偶发错误，因此未据此更改底层 CRC。临时功率测试后已恢复原来的 1 档。

当前日志保留 UID、扇区、块号与 ERROR / IRQ0 / IRQ1 / STATUS；控制器报告射频错误时不会统一断言密钥错误。LOADKEY 失败阻止继续认证或读写。错误位含义参考 [NXP CLRC663 数据手册](https://www.nxp.com/docs/en/data-sheet/CLRC663.pdf)。

## 手动读取流程对齐

手动块读取和工具箱扇区读取现共用 `MifareClassicSession.readBlocks`：仅在射频异常时重新选卡、核对相同 UID，使用同一密钥重读一次；不换密钥。扇区中途读取失败会丢弃该次局部结果，重新认证后完整读取。工具箱移除自身的重读，避免两层叠加。写入仍不自动重发。

手动 Key A / Key B 输入改为明文 HEX，不再显示密码圆点。此修改解决读取流程的恢复差异，不代表底层偶发射频故障已彻底定位。
