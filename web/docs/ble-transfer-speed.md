# Web BLE 传输速度与排查

网页端只使用 Web Bluetooth。射频帧协议与 `tmp/rf_device_platform-python` 对齐。若特征值支持无响应写，网页最多连续发送 3 片后等待一次 ATT 确认，并在帧尾再次确认；发生静默丢帧后逐步收窄窗口，最终退回每片确认。特征值不支持无响应写时始终逐片确认。

## 写入长度

网页按以下信息确定安全单次写入长度，取最大有效值并限制为 244 字节：

1. 浏览器报告的 `device.gatt.maxWriteWithoutResponseSize`。它反映当前协商后的 ATT MTU，确认写使用同一 MTU。
2. 设备回包分片长度，作为已观察到的安全下界。

浏览器和设备都还没有报告长度时，先使用 20 字节保守值。B01 在握手后会通过只读能力查询验证 118 字节候选长度；只有收到与初始能力清单一致的完整回包才采用。失败后发帧分隔符并重新查询确认链路恢复，不再尝试 182 或 244 字节候选值。

## 传输耗时怎么读

刷图日志同时记录传输总耗时、GATT 写次数与等待累计值、协议请求分段和设备作业终态等待。它们用于区分主机分片提交、设备响应和设备执行阶段；这些都是主机观察值，不代表纯空口时间。

近期一组 Web 实测总耗时 52 秒：GATT 写入 371 次、累计等待 24.5 秒；协议计时为提交 24.49 秒、提交后首条接收 1.83 秒、请求回执 3.32 秒、设备作业终态等待 22.29 秒。单次写入长度会影响 GATT 写入次数；设备终态等待仍取决于读卡器、标签和图像写入过程。
